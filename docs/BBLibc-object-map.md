# Tools and object files of BBLibc.dll

Which tools built which parts of `BBLibc.dll` (version 1.01, timestamp
2001-03-15 15:04:56 UTC, linker version 6.00 in the PE header).

## Rich header

The Rich header lists tools which produced object files of the DLL, their
builds and numbers of object files, but not addresses.

|---|---|---|---|---|

Build 8799 of `cl` 12.00 is Visual C++ 6.0 SP4 (8168 is RTM, 8447 is SP3,
8804 is SP5/SP6), the linker 6.00.8447 was not updated by SP4.

## Method

The linker aligns code of each object file and each COMDAT section at 16
bytes and fills gaps with `int 3` (`0xCC`), so `tools/block_map.py` (branch
`claude/block-map`) splits `.text` into blocks, each of them is an object
file compiled without `/Gy` or a COMDAT procedure (inline function, template
instance or procedure generated by the compiler). A block is

- C++ if it has an export with mangled name (`?...`), a procedure from a
  `.cpp` file of BldMystery or a method saving `this` from `ecx` in the
  prologue before writing to `ecx`;
- C otherwise;
- CRT, MASM and import thunks are recognized by their code.

The numbers of blocks roughly match the Rich header: 43 C blocks in the
libjpeg range for 46 C objects, 38 C++ blocks with several procedures for 27
C++ objects. The differences are expected: an object or a COMDAT procedure
ending exactly at a 16-byte boundary has no `int 3` gap, so it is merged
with the next block; pairs of COMDAT procedures are counted as one block;
AliasObj and `lib.exe` objects have no code.

## Source files of BldMystery

Some files of BldMystery are parts of one original object file: their
procedures are in one block without alignment gaps.

| Block | Files of BldMystery |
|---|---|
| 1 | `IDataFile.cpp`, `ODataFile.cpp`, `OpenedFilesFuncs.cpp` |
| 46 | `Name.cpp`, `NamedObj.cpp` |
| 47 | `Resource.cpp`, `ResourceManager.cpp` |
| 87 | `Color.cpp`, `Pal.cpp` |
| 150 | `MeshEdge.cpp`, `ObjDscr.cpp` |
| 223 | `ParticleGType.cpp`, `RDataLight.cpp`, `RDataTriangle.cpp` |

Procedures of `BBLibc.cpp` are in three blocks (26, 140, 221), so they are
probably parts of three original files.

## Limitations

- C and C++ are told apart heuristically: a free C++ function without `this`
  and without an export looks like C.
- Single C blocks in C++ ranges (for example 204-210) are probably procedures
  generated by the C++ compiler, but it is not certain.
- The service pack can't be told from the code, only from the Rich header.
